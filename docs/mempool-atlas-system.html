Mempool Atlas · system architecture

Swim in one mempool. Compare only when the question requires it.

One selected Bitcoin node and its observed mempool form the primary Mempool Atlas experience. peer-observer records the forensic story, verbose RPC reconciles what is present and supplies display facts, and the central service keeps each source projection independent. A fork comparison can consume multiple source snapshots without turning them into one mixed mempool.

Evidence plane

peer-observer captures admission, removal, replacement, rejection, peer context, and raw transaction evidence. Mempool evidence is fully retained, while P2P capture defaults to inbound sightings. Those sightings preserve pre-validation peer evidence. Full raw relay capture remains available for bounded diagnostics. NATS slow consumption and disconnects become durable source-scoped gap markers because missing forensic history cannot be recreated.

State plane

RPC is authoritative for one node's current mempool at poll time. Its common Core and Knots subset supplies virtual size, exact base fee in satoshis, and node entry time. A projection fence orders snapshot formation against peer-observer capture, so reconciliation repairs drift and enriches pending entries without overwriting newer evidence or storing each complete poll as an event.

Delivery and projection

The durable local outbox drains in strict FIFO order with at-least-once delivery. Live evidence stays on the single-event path, while contiguous RPC corrections use an atomic batch of at most 512 events and 4 MiB. A complete, same-order 202 acknowledgement removes the whole prefix; otherwise none of it is removed. Membership facts and capture integrity remain partitioned by source.

Extensible interpretation

Comparison remains an optional consumer; classifiers are required for the MVP. Fork policy, data carriage, and future heuristics can evolve without changing a source snapshot or the underlying observation model.
