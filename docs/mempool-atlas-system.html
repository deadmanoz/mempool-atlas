Mempool Atlas · bounded SourceReplica architecture

Correct state, guarded writes, and hard deployment containment.

RPC is the sole authority for current membership. Each source replica is constrained first by logical limits, then by SQLite admission, and finally by a fixed filesystem image and a resource-limited service. The central reader sees only complete active generations. Peer and forensic evidence remains a separate, deferred product.

200,000 entries per source two persistent source IDs fixed data images + cgroups evidence deferred
01

Three safety layers

Each layer controls a different failure mode. Logical limits bound what Atlas represents, SQLite admission decides whether a mutation may begin, and deployment containment prevents Atlas from consuming the host resources reserved for Bitcoin.

Layer 1 · logical

Bound the state model

A source has at most 200,000 current memberships. Changes are coalesced by txid, and delivery holds at most one stable action. The server admits two persistent source identities and keeps no more than one active plus one staging generation for each.

Layer 2 · application

Admit writes before growth

Atlas verifies max_page_count, accounts for the database, WAL, and SHM together, preserves filesystem reserve, and attempts WAL relief before growth. Busy relief is retried; real capacity pressure is explicit.

Layer 3 · deployment

Contain the process and disk

Fully allocated ext4 images put a hard edge around data files. systemd cgroups cap memory and swap while throttling CPU and disk I/O. Required mounts fail closed, so services cannot fall back to the VPS root filesystem.

02

The implemented state path

One state-only agent owns one logical source. The source side is repeated for the two configured production identities. Only the WireGuard path reaches the central state endpoint, and every read is derived from a complete active generation.

03

Convergence and recovery

A write begins only after WAL relief and capacity admission. Normal contention retries without changing the committed replica. A full checkpoint is the safe fallback for bootstrap, pressure, reset, or cursor disagreement.

Capacity from rows to host resources

The limits deliberately overlap. Application checks protect SQLite invariants and preserve headroom. Fixed ext4 images and cgroups are the outer hard boundaries that protect the rest of each VPS.

Application admission and deployment containment are different guarantees.

The SQLite policy checks the main file, sidecars, and remaining filesystem reserve before a mutation. It also tries to truncate an oversized WAL and retries normal checkpoint contention. The fixed ext4 image is the hard disk ceiling even during transient allocation, while the cgroup is the hard process-resource edge. Capacity rejection leaves the last committed state intact: the agent stops protectively and the server rejects the mutation.

05

The production boundary

Current state is deliberately narrow. Network exposure is restricted to the two configured source identities, and evidence remains outside the production membership path until it has its own quotas and archive contract.

Production surface

State and reads only

The agent derives membership only from complete RPC snapshots. The server accepts SourceReplica traffic only over its WireGuard deployment path and requires an exact allowlist of the two configured source IDs. Product queries read active generations only; staging is never discoverable.

Deferred surface

Evidence is separate

Peer sightings, rejections, capture gaps, raw transactions, and forensic archives are reported as not collected today. A future bounded HotStore and verified EvidenceArchive must use separate ordering, disk budgets, shedding rules, and failure behavior. They can never establish membership.
