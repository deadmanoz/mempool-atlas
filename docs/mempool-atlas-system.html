Mempool Atlas · bounded data architecture

Current state must stay correct even when evidence cannot keep up.

The first canaries taught us that one permanent FIFO cannot safely own both current mempool state and open-ended forensic evidence. The new design gives current state its own bounded, convergent lifecycle. It then adds recent evidence and historical archives as separate products with separate quotas and failure behavior.

01

What changed

The old unit of durability was every observation. The new unit is a complete source state plus the smallest bounded information needed to converge it.

Experimental design

One global FIFO for state and evidence

Peer sightings, rejection events, capture gaps, and RPC corrections all accumulated behind the same failed delivery head. Storage grew with event rate multiplied by outage duration. Knots reached 26.87 GiB and exhausted its root filesystem.

Current design

Independent lifecycle for current state

One complete RPC snapshot, one coalesced dirty row per txid, and one frozen delivery action replace the mutation history. A central outage now costs storage proportional to mempool size, not elapsed outage time.

One agent owns one logical source. The central service may co-locate sources, but it never mixes their membership. Solid paths are in the production runtime today.

04

What is bounded now

Semantic bounds stop current state from becoming an open-ended log. The database cap adds a hard local circuit breaker, while transient WAL and filesystem reserve remain explicit deployment work.

4,096

1 GiB

Structure Bound Why it cannot grow with outage duration
Current membership 1,000,000 rows The count is preflighted, then each complete observation replaces current facts.
Dirty state 4,096 rows and 1 MiB estimated Repeated changes to one txid overwrite one coalesced row.
Frozen action One delta or one checkpoint New observations never append another in-flight action.
Central generations One active and one staging per source Unique indexes forbid a third generation.
HTTP payload 4 MiB, with 512 entries per chunk Large snapshots are resumed as bounded deterministic chunks.
Capacity acceptance is not complete yet.

max_page_count bounds the main SQLite file, not a transient WAL burst. A frozen checkpoint may coexist with current membership, and corepc-client buffers the verbose RPC response before decoding. We still need measured two-snapshot and response-buffer overhead plus a filesystem guard that preserves the greater of 20 percent free or 5 GiB before calling the 2 GiB source-VPS envelope production-safe.

05

Three separate data lifecycles

The production destination is not one larger database. It is three products with different value, retention, and failure rules.

Implemented now

SourceReplica

Exact current membership, epoch, revision, and freshness. It prefers checkpoint fallback over incomplete state and must keep converging when evidence is shed or unavailable.

Next slice

Bounded HotStore

Recent rejections, peer metadata, capture gaps, and intrinsic derivations with explicit age, count, and byte quotas. Pressure may shed evidence but cannot block SourceReplica.

After HotStore

EvidenceArchive

Content-addressed raw transaction data and compact sightings in sealed local segments. Delete a segment only after off-VPS size and digest verification.
