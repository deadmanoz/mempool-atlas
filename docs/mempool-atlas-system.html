Mempool Atlas · system architecture

Evidence arrives fast. RPC keeps membership honest.

Each monitored Bitcoin implementation gets the same node-local collector. peer-observer records the forensic story, RPC reconciles what is actually present, and the central service keeps one source-labelled projection per node. Cross-source comparisons are derived on demand, never stored as a merged Atlas mempool.

Evidence plane

peer-observer captures admission, removal, replacement, rejection, peer context, and raw transaction evidence. Collector downtime can leave an unrecoverable forensic gap.

State plane

RPC is authoritative for one node's current mempool at poll time. Reconciliation repairs membership drift without storing each complete poll as an event.

Delivery and projection

The local outbox provides at-least-once delivery. Central storage co-locates source-labelled events, but current membership remains partitioned by source. Comparison sets are computed views, not membership written back into a combined pool.

Extensible interpretation

Transaction facts and classifiers remain optional layers. Fork policy, data carriage, and future heuristics can evolve without changing the underlying observation model.

P2P receipt is not admission absence is not organic rejection central storage is not merged state pruning does not weaken mempool visibility at-least-once delivery is not exactly-once transport
Target architecture with implementation status as of 14 July 2026. Comparisons are computed views over source-partitioned state. No ZMQ dependency is required.
