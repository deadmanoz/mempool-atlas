# Architecture

The self-contained [system architecture visualisation](mempool-atlas-system.html) shows the implemented node-local data path, primary single-source aggregate view, source-partitioned central state, and the implemented classification, rejection, and optional comparison layers.

Mempool Atlas is divided into two Rust process boundaries and one browser client.

## Node-local agent

Each `atlas-agent` instance is bound to one logical source. In `full` mode it subscribes to peer-observer's unframed protobuf events on the Core NATS `mempool` and `netmsg` subjects. All supported mempool evidence is retained. P2P transaction capture defaults to explicitly inbound observations, preserving peer evidence from before node admission or rejection; `ATLAS_P2P_POLICY=all` retains the full P2P transaction relay stream for a bounded diagnostic run. This is a volume policy over peer sightings, not transaction deduplication, and the observation model remains extensible enough to represent either policy. Supported observations are assigned the configured source ID, a per-process source session, and a transactionally allocated local sequence before they enter the durable SQLite outbox. In `rpc-only` mode the NATS input is omitted without claiming that the missing forensic evidence exists.

The outbox also stores an effective local membership projection. Every queued membership mutation updates that projection in the same SQLite transaction, even if central delivery is still pending. A missing key is absent, a present key with no facts is awaiting RPC enrichment, and a present key with facts carries the last verbose RPC result. Periodic `getrawmempool true` snapshots are compared with this projection and produce explicit `mempool_reconciled` corrections for removals, additions, pending entries, or changed facts. The required Core and Knots subset is virtual size, exact base fee in integer satoshis, and the node's local mempool entry time. Unknown response fields are ignored; missing, malformed, overflowing, or non-exact JSON integer facts reject the whole poll. RPC therefore repairs and enriches current membership, while peer-observer contributes lower-latency timing and evidence that polling cannot recover, including organic rejection and short-lived transaction events.

Capture enqueue and RPC snapshot reconciliation share a projection fence. The RPC side holds it from immediately before snapshot formation until the resulting corrections commit. This prevents an older snapshot from overtaking a newer peer-observer mutation. The fence does not hold a SQLite transaction open during the network RPC call.

Delivery is an independent runtime capability. It starts from the persisted FIFO head even when NATS or RPC is unavailable, while the input capabilities reconnect separately. Live and other non-reconciliation evidence continues through the single-event endpoint. A contiguous prefix of `mempool_reconciled` events is transported as a batch of at most 512 events and 4 MiB. This changes transport granularity only: every event keeps its source, session, sequence, and evidence identity, and later live evidence never overtakes the prefix.

The server applies a reconciliation batch sequentially in one SQLite transaction and returns one ordered acknowledgement per event. The agent atomically removes the prefix only after a complete same-order HTTP 202 response. Network errors, non-202 responses, malformed or mismatched acknowledgements, and server conflicts retain the entire prefix. A crash or lost response after central commit retries the same events, which central ingest recognizes as duplicates. No new checkpoint or source-reset semantics are introduced.

Periodic capture accounting makes the volume policy observable by reporting persisted and policy-suppressed observations with the pending outbox depth. An intentional outbound suppression is not reported as evidence loss. A NATS slow-consumer notice is persisted as known capture loss and a disconnect as possible capture loss. These markers describe historical peer-observer evidence integrity. RPC reconciliation may repair current membership, but it never clears or weakens capture-gap history.

The agent database is part of the source's durable identity and must use persistent storage. One agent writer and one database are allowed per source, and an existing database refuses a different source ID. Losing it discards pending evidence and the effective projection, so deleting it is not a supported reset path. An explicit protocol for resetting or rebaselining central source state after database loss remains deferred.

## Central service and browser

`atlas-server` ingests normalized events idempotently through a single-event endpoint and an atomic reconciliation-batch endpoint, reduces current membership and capture-gap state into SQLite, and exposes read-only browser data. `GET /api/v1/sources/{source_id}/mempool` returns one source snapshot containing current membership, atomic node-reported fact state, last accepted evidence time, and historical capture integrity. A peer-observer admission is returned as `awaiting_rpc` until reconciliation supplies the three facts. Removal deletes the current projection row, so a later re-entry cannot inherit stale metrics.

The visualization workbench consumes an aggregate-only read model instead of per-transaction rows. `GET /api/v1/sources` lists known sources for discovery, and `GET /api/v1/sources/{source_id}/mempool/summary` computes totals, per-dimension `{count, vsize}` histograms, and optional per-classification fee-rate ECDF and joint fee-rate by virtual-size detail blocks in one pass over the fact-bearing membership. The canonical bin edges live in `atlas-model` and are emitted with every summary, so clients never hardcode them and payload size is fixed by the bin catalog rather than mempool depth. Filter facets are applied server-side with known-to-match semantics, entries awaiting RPC facts are reported only as a separate count and never enter a vsize sum, and source health travels in the same payload so the honesty banner always reflects the same instant as the bins. Golden read-API fixtures under `fixtures/api/` are kept equal to live router responses by a contract test and are regenerated with `just regen-api-fixtures`.

`GET /api/v1/sources/{source_id}/rejections` exposes `mempool_rejected` evidence as a distinct, honestly bounded read model rather than as membership. A rejection records a source policy refusal at one instant; it is never current state and is never conflated with `mempool_removed`, so the query filters on the `mempool_rejected` event kind alone. A partial index bounds the scan by the recent window rather than the whole event log. The aggregate covers the most recent thousand rejections: a total count, the window's oldest and newest observation times, and node-provided reason strings counted most-frequent-first with a bounded distinct set and an explicitly marked long-tail rollup. Classification attribution is best-effort and explicit about its limits: a refusal classifies at read time only when Atlas has observed matching raw bytes and derived intrinsic facts for that txid, whether that observation preceded or followed the refusal. The window therefore partitions into a classified count with per-taxonomy verdict breakdowns (a classified transaction with no verdict for a taxonomy takes that taxonomy's honest `unknown`) and an unclassified count that is reported plainly and never guessed. The recent list is a separately cursor-paginated slice of the same rejection stream, newest first, each record carrying the refused txid, reason, observation time, evidence event id, and any derived verdicts; the cursor encodes `(observed_at_ms, event_id)` and pages strictly older refusals until exhausted.

Shape facts and classification are server-side derivations from evidence, not new evidence. When `p2p_transaction` evidence carries raw bytes, ingest parses them once, verifies they reproduce the claimed txid and wtxid, derives the intrinsic shape (total output value in integer satoshis, input and output counts, and the canonical script type under a documented dominance rule: most frequent output type by count, ties broken by summed value, then catalog order), runs every registered in-process classifier pack from `atlas-classifiers`, and persists one `transaction_shape` row plus one `transaction_classification` row per taxonomy per txid. Intrinsic facts are shared across witness variants and across sources. The baseline heuristic pack applies ordered, documented tells (coinjoin, consolidation, batch, data via OP_RETURN or inscription envelope, lightning via anchor outputs, payment) and records its rule and trigger values as evidence; heuristics are labelled as such, not ground truth. Undecodable or identifier-contradicting bytes leave the transaction underived rather than guessed. Classification is multi-taxonomy: each pack declares its taxonomy (key, label, and ordered verdict vocabulary including a mandatory `unknown`), the summary carries one histogram per registered taxonomy plus the taxonomy descriptors themselves, filters arrive as per-taxonomy `t.<key>` facets validated against the registry, and the browser renders whatever taxonomies the wire declares. In the summary, every available shape histogram carries an explicit `underived` bucket for matching rows without shape evidence; taxonomies instead assign such rows their honest `unknown` verdict. RPC-only deployments therefore keep working with fully honest underived reporting.

The dependency-free browser's primary view is the aggregate workbench. It discovers sources through the listing endpoint, polls the summary endpoint every five seconds, and renders classification and script filter chips, a switchable composition or squarified-treemap hero, a per-classification fee-rate ECDF, and a joint fee-rate by virtual-size heatmap with marginals, all from server-computed bins so DOM size is bounded by the bin catalog regardless of mempool depth. Facets without derived evidence render as explicitly unavailable rather than empty, and the capture-honesty banner is driven by the health block of the same summary payload. Per-transaction detail is an on-demand inspector: opening it fetches the full membership snapshot and renders the static Canvas 2D swim view (fee-rate bands by entry-age bands, glyph area following virtual size, deterministic transaction-ID jitter, a neutral awaiting-RPC strip) plus the bounded, paginated table. The derived base fee rate does not claim to represent ancestor-package mining priority.

Central storage is shared operationally, not semantically. Every event remains labelled with its `source_id`, `current_membership` is keyed by `(source_id, txid)`, and capture integrity is projected per source, so the same transaction or capture condition in Core and Knots produces independent source state. Transaction variants can be deduplicated by `wtxid` because the serialized transaction is an intrinsic fact rather than source state.

The comparison workspace is the optional derived layer, implemented as a read-time endpoint. `GET /api/v1/sources/compare` takes an ordered list of two to four source IDs and derives, entirely in SQL over the source-partitioned `current_membership`, a shared-by-all region and one staged membership-set difference per adjacent pair: transactions present in `to` and absent from `from`, aggregated with the designated `to` facts, plus the reverse set difference as an anomaly count. Only aggregates leave the server, no combined mempool is stored, and the caller-asserted permissiveness ordering is reported against rather than enforced. A non-empty reverse difference is surfaced as unexpected, never hidden. Neither direction proves filtering, rejection, or relay causality. Shape and classification are intrinsic to a txid, so a region's taxonomy attribution is source-independent; fee-rate and age come from the region's designated source. Rejection evidence is not joined into the comparison: each source's rejections stay a separate panel, preserving the rule that absence is not rejection.

One selected source is the primary Atlas mempool view. Atlas never constructs a combined cross-source mempool. The optional comparison workspace computes shared and divergent membership sets from two or more independent source projections at read time. A fork deployment may make that workspace the landing view without changing Atlas storage semantics or the long-lived single-source product.

The shared model never hard-codes Core, Knots, fork heights, or deployment hostnames. Fork-specific source profiles and required MVP classifier rule packs are configuration layered on top of the generic observation model.

## Operations

Both central and agent SQLite operations run through `scripts/migrate-safe.sh`, which creates and validates a backup before changing an existing database. Every Atlas-owned connection keeps SQLite temporary tables, indices, and statement journals in memory. This removes the operating-system temp-directory dependency from those runtime paths; the configured database directory must still permit the database, WAL, and SHM files. The setting is an intentional sandbox-compatibility tradeoff, and transient query memory can grow with concurrent query work. The central clean preproduction schema is generation 6, which includes the partial `event_rejection_idx` used by bounded recent-rejection lookups. The source-bound agent outbox schema remains generation 3. Fresh databases use `just db-migrate-dev` and `just agent-db-migrate-dev`; every stale generation is rejected. Replace an existing preproduction deployment by stopping every Atlas process, running `just db-reinitialize-deploy` centrally and `just agent-db-reinitialize-deploy` for every source, then restarting matching server and agent binaries. The reinitialization commands preserve verified backups and central plus source state must be replaced as one coordinated operation.
